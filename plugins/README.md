# Plugins Mirador installs by itself

`defaults.json` lists the plugins Mirador installs into `~/.mirador/plugins` by itself: each with its `name`, the git `repo` it clones, and the release `tag` it installs at. At a start, Mirador installs each one it hasn't installed before, and remembers it did; one that didn't install, offline say, is tried again at the next start. After that they are plugins like any other: Settings lists them with their updates and a Remove button, and one the user removed stays removed. `MIRADOR_DEFAULT_PLUGINS` names another such file, or `off` for none.

Every plugin gives its release in its `plugin.json` as `version`, `x.y.z`, or it doesn't load, and tags each release `v<version>` in its repo. Added without a branch, a plugin installs at its newest release tag and its updates are newer releases; a release whose `plugin.json` gives another version than its tag is refused. A repo that tags no release installs from its default branch, and a plugin added with a branch follows that branch's commits, even once the repo tags releases: remove it and add it again to follow the releases.

A plugin's settings go in its `plugin.json`, as `settings`: each with an `id`, a `label`, an optional `hint`, its `choices` (a `value` and a `label` each) and the `default` value. Settings shows them under the plugin, and Mirador keeps what the user chose, the same in every browser. An item type that sets `opensWithRoom: { setting: "<id>" }` opens full screen or beside the chat as that setting says, so its choices must be `fullscreen` and `beside`; the code review plugin's "Open reviews" is one.

A plugin describes itself in its `plugin.json` too, for Plugins…: `description`, a sentence or a few on what it does, for its page; `tagline`, one line for its tile, up to 120 characters; and `screenshots`, pictures of it at work, each `{ "path", "caption" }`, with the path a PNG, JPEG, GIF or WebP file inside the plugin's folder. Once the plugin is installed they show instead of the catalog's, so a plugin the catalog doesn't list shows them too, and a field it leaves out shows the catalog's.
